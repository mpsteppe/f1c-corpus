## sub_6D987A_006d987a — scan_tree — run-length scan of code lengths

**Summary:** Scans the per-symbol Len words of a Huffman tree in index order and run-length-counts them into the code-length tree (bl_tree): runs shorter than min_count add count to bl_tree[len].Freq; longer runs of a nonzero length bump bl_tree[len].Freq (when the length changes) plus the REP_3_6 entry; long zero runs bump REPZ_3_10 or REPZ_11_138. Writes a 0xFFFF guard length past the last symbol. Matches zlib's scan_tree, used when emitting a dynamic-block header.

**Guard conditions:** if tree[0].Len (0x2) == 0 → max_count=138, min_count=3, else 7/4. The scan loop runs only when max_code (a2) >= 0. Per symbol: continue accumulating the run while ++count < max_count && curlen == nextlen (LABEL_23 path). Otherwise, when count >= min_count: if curlen != 0 → (if curlen != prevlen) bl_tree[curlen].Freq++ and bl_tree[REP_3_6].Freq++ (a3[1370]); if curlen == 0 → count > 10 ? bl_tree[REPZ_11_138].Freq++ (a3[1374]) : bl_tree[REPZ_3_10].Freq++ (a3[1372]). When count < min_count → bl_tree[curlen].Freq += count (a3[2*curlen+1338]). After an emit: count=0, prevlen=curlen, then limits recomputed: if nextlen == 0 → 138/3; else if curlen == nextlen → 6/3; else 7/4. The write of tree[max_code+1].Len = 0xFFFF happens unconditionally before the loop.
