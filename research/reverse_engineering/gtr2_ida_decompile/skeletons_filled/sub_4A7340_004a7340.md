## sub_4A7340_004a7340 — state-code update and virtual notification

**Summary:** Guarded state update: when the object's guard field this[70] is nonzero, it looks up a per-state byte from the global table byte_B7075C (indexed by a global state handle), derives a state code (0/1 or 4/5) from that byte and the object's byte-field predicate, stores it at this+0x10C and passes it to the object's virtual slot +0x2C. If the guard field is zero, it simply returns that zero.

**Called by:** sub_4B4AE0 (004b4ae0)

**Struct fields accessed:**

| Base | Offset | R/W | Init (literal → value) | Purpose |
|------|--------|-----|------------------------|---------|
| obj | 0x2C | R | — | Virtual slot at vtable offset 0x2C, invoked with the freshly computed state code |
| this | 0x0 | R | — | Vtable pointer read to dispatch slot +0x2C |
| this | 0x10C | RW | 1 | Current state code (this[67]); assigned 4/5 when the byte-field predicate is nonzero, 0/1 otherwise, then forwarded to the virtual call |
| this | 0x118 | R | — | Guard field (this[70]); when zero the whole update is skipped and this value is returned |

**Written-by note (persistence):**
- this 0x10C: written conditionally on every invocation that passes the this[70] guard; an external poke survives only until the next such call (the value is recomputed from the predicate and table byte each time).

**Guard conditions:** First guard: `this[70]` (offset 0x118) — if **zero**, return it immediately, no state write and no virtual call (BLOCKED). If nonzero, proceed: the looked-up byte `v3` and `sub_4CD650(this)` choose the code — predicate nonzero + v3 nonzero → 4; predicate nonzero + v3 zero → 5; predicate zero + v3 nonzero → 0; predicate zero + v3 zero → 1. Then virtual slot +0x2C is called with that code as argument, and its result is returned.
