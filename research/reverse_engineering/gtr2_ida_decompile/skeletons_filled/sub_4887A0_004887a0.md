## sub_4887A0_004887a0 — StartUiThreadAndWait

**Summary:** Startup orchestrator: clears the shared UI state word (under hMutex), creates the UI thread at sub_487D50 storing its handle at this+0x354, then spin-waits (Sleep(1) polls) until the shared state reaches 1, runs four sub_4804E0 calls, sets the state to 2 and returns. Boot sequence between the game and its Windows UI thread.

**Called by:** sub_489660 (00489660)

| this | 0x354 | RW | — | UI thread handle returned by CreateThread (thread id written at this+0x358 via `this + 214`) |

**Written-by note (persistence):**
- this 0x354: written once each time this init routine runs, with the newly created thread handle. Not recalculated per frame; an external poke survives until this function is run again.

**Guard conditions:** Shared-state writes read/write unk_759EA8 only when `hMutex != 0` and `WaitForSingleObject(hMutex, dwMilliseconds)` returns 0 or 128 (otherwise the pointer is 0 and the write goes through null). The wait loop ends as soon as one poll sees shared state exactly 1; then and only then are the four sub_4804E0 calls made and the state set to 2. Any other state value (0, or 4 on UI shutdown) leaves the loop spinning (Sleep(1) each pass).
