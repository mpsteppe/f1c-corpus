## sub_5FC840_005fc840 — Per-element vertex/index buffer upload

**Summary:** One-shot uploader: when the object's 0x200000 flag is clear, it locks/creates two buffers (vertex and index style) through the global manager dword_FB27A4's vtable slots 404/444, bumps each buffer's +12 usage counter, marks the flag, fills the write pointers — copying 64-byte-scaled element data into the first buffer and writing 16-bit index words (with a running base-vertex offset added) into the second — then unlocks both buffers via slots 416/456. Returns 0, or -1 if either buffer operation fails.

**Guard interpretation:** Whole body is BLOCKED when `(*this & 0x200000)` is already set (returns 0 immediately). Inside: the first vtable call (slot 404) returning nonzero → return -1 (first buffer failure); the second (slot 444) returning nonzero → return -1 (second buffer failure). The copy/fill block runs only when both write pointers (v8 from first buffer +0x4C, v9 from second buffer +0x20) are non-null; the per-element loop then runs only while the count a1[11] > 0 and stops after `v11+1 >= a1[11]` iterations. Within the loop, flag 0x400 selects the source pointer (a1[13]+128 per 132-byte record) versus the default a1[20]. Flag 0x200000 is set only after both locks succeed.
