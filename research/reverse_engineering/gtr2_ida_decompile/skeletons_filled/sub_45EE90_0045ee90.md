## sub_45EE90_0045ee90 — mouse cursor update and cursor-mode parameter setter

**Summary:** Win32-side mouse handling: dispatches on command code a4 to either store/accumulate configuration values in fields 0xB0-0xBC, or (any other a4) process a new cursor position a2/a3 — clamping to the bounds held in fields 0x0-0xC, accumulating movement in 0x18/0x1C, and either warping the OS cursor to the Rect centre (captured/relative mode, byte at 0xC0 set) or storing the clamped position. Recomputes the scaled float outputs at 0x28/0x2C from the scale factors at 0x20/0x24.

**Written-by note (persistence):**
- this 0x10: written only on a movement update (delta nonzero); overwritten by the next movement — an external poke survives until the next cursor move.
- this 0x14: written only on a movement update; overwritten by the next move.
- this 0x18: incremented on each movement update; an external poke offsets the running accumulation and is not restored.
- this 0x1C: incremented on each movement update; a poke offsets the running accumulation.
- this 0x28: recomputed from this[4] and the scale after every movement update; poke lost on the next move.
- this 0x2C: recomputed from this[5] and the scale after every movement update; poke lost on the next move.
- this 0xB0: written only when a command with a4==0 arrives; a poke survives all other calls but is replaced at the next a4==0 command.
- this 0xB4: written only when a4==1; survives until the next a4==1 command.
- this 0xB8: written only when a4==2; survives until the next a4==2 command.
- this 0xBC: accumulated (+= a5) when a4==3; a poke is absorbed into the running total and never restored.

**Guard conditions:** The a4 switch is the dispatch: a4==0/1/2 store a5 into 0xB0/0xB4/0xB8 and a4==3 accumulates a5 into 0xBC; any other a4 takes the movement path — PASS into movement requires a nonzero delta ((a2-this[4]) || (a3-this[5])), otherwise nothing is updated. Inside movement, the byte at 0xC0 decides the branch: if nonzero, captured/relative mode — cursor position is recentred ((max+min+1)/2 on both axes) and SetCursorPos warps the OS cursor to the middle of the global Rect; if zero, the new position is stored and clamped into [this[2],this[3]] on x and [this[0],this[1]] on y. After either branch the scaled floats at 0x28/0x2C are always recomputed.

**Guard interpretation:** Command dispatch is by exact a4 values 0-3 (jump table); a4 outside 0-3 falls to the default movement path, so any unexpected command value is treated as a cursor-coordinate update rather than being rejected. Within movement, the zero-delta check blocks all state updates (including the scaled floats) when the position did not change. The 0xC0 flag selects between clamp-and-store (mouse follows coordinates) and accumulate-and-recentre (relative/captured mouse): the former clamps into the stored bounds, the latter additionally forces the OS cursor back to the window centre every processed movement.
