## sub_64460A_0064460a — Best-match search over candidate list (metric + exact-key short-circuit)

**Summary:** Scans a 0-terminated array of record IDs, resolving each via sub_644568 and comparing against the query record a3 with the sub_644593 metric; returns the query key immediately on an exact key hit, otherwise the best (lowest-metric, tie-broken) candidate, or a default record's key if none qualify.

**Called by:** sub_64A702 (0064a702)

**Struct fields accessed:**

| Base | Offset | R/W | Init (literal → value) | Purpose |
|------|--------|-----|------------------------|---------|
| this | 0x0 | R | — | First dword of a record — the record key/ID compared for exact match and returned |

**Globals referenced:**

| Address | Name | R/W | Role |
|---------|------|-----|------|
| 00735fe8 | unk_735FE8 | R | Default record used as initial "best" holder; its first dword is returned when no candidate matches, and its dword at +8 seeds the tie-break comparison |

**Functions called:**

| Address | Name | Purpose |
|---------|------|---------|
| 00644568 | sub_644568 | Resolves a candidate ID to a record pointer |
| 00644593 | sub_644593 | Computes the comparison metric between query record a3 and candidate record |

**Guard conditions:** Candidate filtering: array element `v8 == 0` → list end, return best-so-far (`*v5`). For a resolved record `v6`: `*v6 == 0` (empty record) → candidate skipped. Candidate is only compared when `v6[1] != 1 || a2 != 0` — i.e., records with `v6[1] == 1` are skipped unless flag a2 is set. Comparison: exact key hit `*a3 == *v6` → immediately return `*a3` (no metric computed). Otherwise the candidate replaces best only if `metric != -1 && metric <= best && (metric != best || v6[2] < v5[2])`; ties go to the smaller `v6[2]` value.
