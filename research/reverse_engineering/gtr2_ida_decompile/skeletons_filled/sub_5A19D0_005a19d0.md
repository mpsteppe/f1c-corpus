## sub_5A19D0_005a19d0 — Network receive pump (select/recv loop with mutex-guarded connection lists)

**Summary:** Polls a socket with a zero-timeout select() and feeds received data through the connection-list machinery: it walks two mutex-protected lists of connection objects to find the entry matching the socket, parses 4-byte frame headers from each connection's ring buffer, and on complete frames resolves the connection address, timestamps it, and dispatches the payload (via the vtable slot at +88). Handles WSA error codes with a jump table and re-enters through off_16C946C on transient failures.

- *(*(*(this+0xAD0)+0x4)+0x0) 0x2C: written only when a received packet matches a connection by address — untouched otherwise, so a poke survives until a matching packet is processed.

**Guard interpretation:** select() == -1 is an error (reported via sub_59BBD0(-1)); select() == 0 means nothing readable. A connection is only considered "with data" when a list walk finds a node whose socket (+32) equals s AND socket != -1, and only parsed when its buffered count >= 4 (v4 / v38 checks). Frame processing additionally requires v19 > 0 && v19 <= 0x604 and the exact length test `v19 == v81 + v80 + 4`. On recv() == -1 the WSA error switch decides: codes 10014/10022/10038/10045/10050/10052/10053/10057/10058/10060/10093 fall through to the tail continuation; 10040 grows the buffer to 512 and continues; 10054 exits immediately in the datagram path; any other code exits. recv() == 0 triggers the "Closed Gracefully" cleanup.
