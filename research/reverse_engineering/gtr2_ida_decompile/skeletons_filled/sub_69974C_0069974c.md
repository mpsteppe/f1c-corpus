## sub_69974C_0069974c — ResolveIdentifierToAST (shader/effect compiler symbol lookup)

**Summary:** Resolves an identifier reference in the effect/shader compiler: walks the scope chain for a symbol of the requested type (`a2`), reports type mismatches and loop-control-scope conflicts, detects ambiguous overload matches via argument matching (`sub_698115`/`sub_6969D2`), and builds the resulting AST node (with a `Values` list for argument counts). When no symbol exists it falls back to built-in type names (`bool`, `int`, `half`, `float`, `double`, `dword`, `vector`, `matrix`, `string`, `texture`, `pixelshader`, `vertexshader`, and `NxM` suffix forms) and finally reports `undeclared identifier`.

**Guard conditions:** Both out-params are cleared first (`*a8 = 0`, `*a9 = 0` when non-null). Scope walk: candidates with a type code different from `a2` produce error 3005 (`E_FAIL`, -2147467259) when `(a7 & 5)` is set, otherwise a lower-priority candidate is skipped; candidate scoring keeps the best (lowest) `v13`, ties accumulate (up to 0x40 candidates in v62). Exact match (`v64 == 0`) triggers the loop-control-scope conflict warnings when the symbol has flag 11 set and flag 10 clear, emitted only if a conflicting unscoped declaration exists. Ambiguity error 3067 fires only when `(a7 & 4)` is set and a candidate pair fails sub_695259 / sub_6969D2. When a candidate is found: `(a7 & 2)` returns the raw node, otherwise the node is materialized; allocation failure returns `E_OUTOFMEMORY` (-2147024882). Built-in fallback only runs when `(a7 & 2) == 0 && !a9` (with additional `a2`-dependent branches); dimension suffixes accept only `1..4` (`N` alone or `NxM`). If nothing matches and `(a7 & 1)` is set, error 3004 `undeclared identifier` is emitted and 1 is returned.
