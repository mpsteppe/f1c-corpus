## sub_5E6500_005e6500 — Recursive composite destructor

**Summary:** Deep-teardown routine: recursively destroys each child node in the linked list at this+0x44 (unlinking and freeing them one by one), clears a field at +0x1D0 of each child's sub-object, then releases the resource at this+0x2C and — only when flag 0x20000 is set — detaches, destructs and frees the object at this+0x28.

**Called by:** sub_5DB470 (005db470), sub_5E6500 (005e6500), sub_5E6C20 (005e6c20)

**Written-by note (persistence):**
- *(*(*(this+0x44)+0x0)+0x30) 0x1D0: Conditional — written only when a child's +0x30 pointer is non-null; once per destroyed child.
- *(this+0x44) 0x4: Conditional — next pointers rewritten only during node unlinking.
- this 0x28: Conditional — set to 0 only when the pointer was non-null and (for the detach path) bit 0x20000 was set.
- this 0x2C: Conditional — set to 0 only when the pointer was non-null.
- this 0x44: Conditional — head pointer rewritten only when the removed node was the head (or as the walk advances via `this[19] = head` each pass).
- this 0x48: Conditional — rewritten only when it equaled the removed node.
- this 0x4C: Written with the current list head on each pass of the destruction loop; overwritten whenever destruction runs.
- this 0x50: only read (decremented value stored back per removed node) — effectively per-node removal.

**Guard conditions:** `this[17]` null → child-list loop skipped. `*v2` (first child) null → do-loop skipped. Child's +0x30 pointer null → +0x1D0 clear skipped. During removal, node search ends when `*v5 == v3` (found, unlink proceeds) or a null next pointer ends the walk (LABEL_17, node already gone). `this[11]` null → +0x2C cleanup skipped; the free is additionally null-checked. `(*this & 0x20000) == 0` → +0x28 cleanup skipped; inside, a null `this[10]` skips all of it. The routine never returns a value.
