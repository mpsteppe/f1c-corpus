## sub_488A20_00488a20 — Lobby Broadcast to Lobby state machine

**Summary:** State machine that drives the "Broadcast to Lobby" flow: it logs into the CINet lobby (registering first if needed), checks the room name for duplicates, creates the broadcast room, optionally launches the external `GTR2_Reporter.exe` process, and reports failures through MessageBox dialogs. **Guard conditions:** Under hMutex: if WaitForSingleObject(hMutex, dwMilliseconds) returns 0 (WAIT_OBJECT_0) or 128 (WAIT_ABANDONED) the shared block unk_759EA8 is read; if its first dword is 3 or 4 AND the current state (this+0x364) is 0 or 5, the state is forced to 8 (abort). Mutex is released immediately after. The state switch handles only 1/2/3/4/5/8 — any other state returns with no action. Case 1 sets state 2 at entry; the login/registration block runs only if byte_B6CEA0 (dedicated flag) is set; if the CD-key string lpData is null/empty it shows "No CD Key Supplied" and skips login. Login result 0 = success (byte_B6CBC3 = 1); 1/2/5/7/9/0xA show dialogs; 8 triggers Register (result 0 → Login again, 0 → byte_B6CBC3 = 1; 1/2/3/5/6/0xA show registration error dialogs). If sub_47BC30() returns 0 the state is forced to 8; room creation only happens when byte_B6CBC3 is set; a duplicate room name shows a dialog and calls Logout instead of CreateRoom. Cases 2/3: if sub_484A00() is true → GlobalStateSetter(1), this[288] = 0, state = 5; otherwise state = 8. Case 4: sub_47F960(), this[288] = 0, state = 5. Case 5: sub_4888D0 / sub_430B40(..., 8.0) / sub_482360. Case 8: if dword_B640C0 != 2 → sub_430D50(); then WM_CLOSE to dword_B6CE68 and the "keep running" flag v74 is cleared.
