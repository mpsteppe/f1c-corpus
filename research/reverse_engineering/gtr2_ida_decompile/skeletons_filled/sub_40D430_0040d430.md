## sub_40D430_0040d430 — Sound trigger/play per object (Miles `AIL_set_sample_*`)

**Summary:** Triggers a sound on the object: first runs collision response (`sub_40AB70`) which returns 1 to veto playback; otherwise lazily creates the sound instance via `sub_40A410` (stores it at `this+0x58`, owner backlink written), sets the sample file from the definition at `this+0x5C` (loop count 0 when `this+0x14 == 1`, else 1) through `AIL_set_sample_file`/`AIL_set_sample_loop_count`, then writes the one-shot fields (id `a2`, position `a4`, active byte 1) and, when `a7 != 0`, runs `sub_40CEE0` and clears the active byte.

**Written-by note (persistence):**
- *(this+0x58) 0x4: written every call after the lazy-create block — new id `a2` stored; an external poke is overwritten on the next call.
- *(this+0x58) 0x8: written every call — new position pointer `a4` stored; overwritten next call.
- *(this+0x58) 0xC: written to 1 every call, then conditionally cleared to 0 when `a7 != 0`; an external poke is overwritten on the next call.
- this 0x58: written only when it was null at entry (lazy creation via `sub_40A410`); a previously set pointer survives.

**Guard interpretation:** (1) `sub_40AB70(...)` nonzero → return 1 immediately (playback blocked by collision response). (2) `*(this+0x58) == 0` → create instance via `sub_40A410(*(this+0x54), a2, a4, a7)`; null → return 1 (creation failed); success stores the pointer and backlink. (3) Inside creation: the sample handle at instance `+0x10` must be nonzero, the definition `*(this+0x5C)` must be nonzero, and a definition filename must exist before `AIL_set_sample_file`/`AIL_set_sample_loop_count` + `sub_40A380` run. (4) `this+0x14 == 1` → loop count 0; else loop count 1. (5) `a7 != 0` → `sub_40CEE0(this)` and active byte cleared to 0; otherwise it stays 1 after the normal write. Always returns 0 on the playback path.
