## sub_487D50_00487d50 — UiMessageLoopThread

**Summary:** UI thread body: creates five modeless dialogs (resource IDs 0x6C, 0x66, 0x67, 0x68, 0x6A) as desktop windows with their own dialog procedures, sets shared UI state to 1 under a mutex, runs the classic Win32 GetMessage/IsDialogMessage/Translate/Dispatch loop, then hides and destroys the dialogs and sets shared state to 4. The game's main Windows UI pump.

**Guard conditions:** Mutex-guarded writes: shared state set to 1 before the loop and to 4 after cleanup only when `hMutex != 0` and `WaitForSingleObject(hMutex, dwMilliseconds)` returns 0 or 128 (otherwise v15/v18 point to 0 and the write goes through null). Message loop: continues while `GetMessageA != 0`; a return of -1 (error) breaks the loop. A message is only TranslateMessage'd + DispatchMessageA'd when IsDialogMessageA returns FALSE for ALL four managed dialogs (hDlg, hWnd, dword_B6CE78, dword_B6CE68) — messages consumed by any of them are skipped. Cleanup unconditionally hides and destroys those same four dialogs (the 0x6C dialog in dword_B6CE6C is neither).
