## sub_49C5A0_0049c5a0 — StartHostedSession (create multiplayer race room, monitor page)

**Summary:** Front-end routine that starts a hosted multiplayer race: builds the room/game name (defaulting or reading it from the host context), checks the name is free in `CINet`, computes the race length from the loaded session config (`RaceLaps` or `RaceTime`) times a race-type scale factor, resets the per-client slot table, switches to the `MONITOR_MPHOST` page, and calls `CINet::CreateRoom` when hosting is active. On name collision it shows an error and jumps to the `JOIN FAILURE PAGE`.

**Guard conditions:** If global mode `dword_B640C0 == 5`, the whole start sequence is skipped: only `sub_478700(&dword_B6CBA8)` is evaluated and `MONITOR_MPHOST` is activated if true, then the function returns -1. The room-existence rejection fires when `byte_B6CBC3` (hosting active) is set and `CINet::RoomExists(dword_B6CBB0, name)` is true → error message, `JOIN FAILURE PAGE`, return -1 (no room created). Room-name selection: context name (sub_473AE0) wins; otherwise stored name `byte_B6DC34` when non-empty; otherwise a generated default. Race length: `byte_B729E8` true → `RaceLaps` × scale factor; false → `RaceTime` × scale factor; either lookup requires `sub_53A250(0)` nonzero and the entry present. `CreateRoom` is only reached when `sub_47BC30()` is true and `byte_B6CBC3` is set. If `strlen(byte_B6DC50) == 0`, `sub_473A80(0)` is called to supply a name.
