## __fltin2_0063859e — Float input conversion core (strtod/atof backend)

**Summary:** C runtime float-conversion engine behind atof/strtod: parses a numeric token, classifies range/NaN/Inf conditions, and fills a caller-supplied result structure with status flags, consumed-character count, and the parsed value. Part of the Borland-style CRT numeric conversion subsystem.

**Called by:** _atof (00631c76), _strtod (00634c77)

**Struct fields accessed:**

| Base | Offset | R/W | Init (literal → value) | Purpose |
|------|--------|-----|------------------------|---------|
| this | 0x0 | RW | — | Output status/flag word (v2): 0x200 on the range-error path, 0x80 and/or 0x100 for special-value classifications |
| this | 0x4 | RW | — | Number of input characters consumed by the parse (v7 − a2) |
| this | 0x10 | RW | — | Low word of the parsed value (v8); zeroed on the range-error path |
| this | 0x14 | RW | — | Second word of the parsed value (v9); zeroed on the range-error path |

**Written-by note (persistence):**
- this 0x0: written unconditionally on every call before return (status word assigned from v2); an external poke is overwritten by the next atof/strtod conversion.
- this 0x4: written unconditionally (`a1[1] = v7 - a2`); recalculated per call, pokes do not survive.
- this 0x10: written on both paths (0 on range error, else parser output from sub_64094B); pokes overwritten next call.
- this 0x14: written on both paths (0 on range error, else parser output); pokes overwritten next call.

**Functions called:**

| Address | Name | Purpose |
|---------|------|---------|
| 006349bb | sub_6349BB | unknown — no direct call visible in the decompiled body (call folded into inlined parser code) |
| 0064094b | sub_64094B | Examines the parsed internal value; returns 1 or 2 to signal a special (NaN/Inf/overflow) classification |
| 00641ce6 | sub_641CE6 | Core number scanner: parses the input token into the internal double buffer and returns classification bits in its result |

**Guard conditions:** If `(v3 & 4) != 0` (scanner flagged a range/overflow condition) → status = 512, parsed value words zeroed, no classification bits added. Otherwise: `v4 = sub_64094B(...)`; `(v3 & 2) != 0 || v4 == 1` → status |= 128; `(v3 & 1) != 0 || v4 == 2` → status |= 256. No early return — every path writes status, count, and both value words into the output struct.
