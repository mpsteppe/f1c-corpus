## sub_5231D0_005231d0 — Window-limited bulk record importer into 848-byte pool

**Summary:** For a key window [a2, a3] (width clamped to at most 1.6670001), locates the first list node whose leading float key reaches a2 — walking forward with node+4 links or backward with node+8 links depending on where the cursor sits — then for every node whose key is <= a3 seeks the node's stream offset (stream object at this+0x6F4, vtable slots 0x1C read / 0x34 seek), skips a 6-byte header (4+2 read), reads the node's record count records via sub_5212F0, optionally rewrites the record header bits, and appends records whose header class is not 0x20000000 into an 848-byte pool (cap 1023) with sub_51BFA0.

**Guard conditions:** (1) a2 == a3 → entire body is skipped (no work). (2) Window clamp: when a4 != 0, a2 is raised to a3−1.6670001 if below; otherwise a3 is lowered to a2+1.6670001 if above. (3) Entry gate: either the cursor node and its payload are nonzero, or the fallback selection (ref>=a2 picks *v8, otherwise this+0x760) yields a node with a nonzero payload. (4) Direction: payload key <= a2 → forward walk via +4 links (stop when key >= a2, then jump to the record loop); key > a2 → backward walk via +8 links (stop when key < a2 → sub_473B70 supplies the node), else fall back to the head. (5) Record loop per node runs while payload key <= a3; the inner read loop runs exactly payload WORD+8 times. (6) Insertion filter: a record is placed into the pool only when (header & 0xE0000000) != 0x20000000 — the 0x20000000 class is skipped. (7) Pool cap: count >= 1023 reuses the current off_9034A4 slot without increment/advance; otherwise the slot is taken and off_9034A4 advances by 848.
