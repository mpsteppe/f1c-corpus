## sub_5E6120_005e6120 — Two-branch state update with triple-value fetch

**Summary:** Update routine for a flagged object: depending on bit 15 (0x8000) of *this it either uses the object's own triple-value getter or, when the state field equals 2, first fetches a triple via sub_5DCE20, then runs a common processing tail (reset at this+0x10, float processing, string scan) and finally sets bit 0x40 in *this.

**Guard conditions (deterministic — field vs literal):**

| Base | Offset | Test | Value | Field / meaning |
|------|--------|------|-------|-----------------|
| this | 0x48 | == | 2 | State/enum selector: only value 2 allows the secondary processing path (the one that fetches the triple via sub_5DCE20) to run |

**Guard interpretation:** Bit 15 (0x8000) of *this is checked first: if set, the primary path runs (sub_5E5C70 fetch + processing tail) without any 0x48 test. If clear, the state object this[13] is fetched and the guard field this+0x48 == 2 is tested: equal to 2 → secondary path runs (sub_5DCE20 + sub_5E5C70 + shared tail); not equal to 2 → everything is skipped and execution jumps straight to `*this |= 0x40` and return. Both passing paths converge on the same tail and set bit 0x40 in *this.
