## sub_45F160_0045f160 — DirectInput joystick poll and axis/POV/button post-processing

**Summary:** Polls the joystick device at this+0x80 (Poll then an 80-byte GetDeviceState — a DIJOYSTATE-shaped block: 8 axes, 4 POVs, 24+ button bytes), with a re-Acquire retry rate-limited to once per 3 seconds on input-lost/not-acquired errors. Copies axes into this+0x398..0x3B4, normalizes each of the 8 axes into this+0x3B8.. (centre/limit/scale/curvature treatment producing a signed [-1,1] value), stores the 4 POV values into this+0x3F0..0x3FC, and stores 24 button flags (bit 7 of each button byte) into this+0x3D8..0x3EF.

**Guard conditions:** this+0x80 decides everything: if the device pointer is null the function returns immediately with no effect. GetDeviceState errors: the two DirectInput loss errors (-2147024884 / -2147024866) take the recovery path, any other nonzero result returns without updating state (result 0 proceeds). Recovery is gated by |dbl_FB1D20 - flt_B6C4F0| >= 3.0 — if less than 3 seconds have passed since the last attempt the function gives up immediately; within the window it stamps flt_B6C4F0 with the current time, calls Acquire, and only retries GetDeviceState if Acquire returned 0. Per-axis: raw == 0.0 forces the output to -1.0; otherwise if the axis centre (v5-40 floats) is nonzero the value is offset by it, and if the offset value falls outside the per-axis limit (v5-32 floats) the output is forced to 0.0; scaled results above 1.0 clamp to 1.0, and a curvature parameter (dword 48 floats before the output) equal to 1.0f skips the curve; 1.0f is also the exact value that bypasses the curve in the negative branch.

**Guard interpretation:** The whole update is blocked by a null device pointer and by any GetDeviceState error other than the two loss errors. The loss-error path is deliberately rate-limited: it can only re-acquire once every 3 seconds (the |time - flt_B6C4F0| >= 3.0 test fails inside the window), and if Acquire fails the frame is dropped. In the axis math, raw 0.0 maps directly to -1.0 (special-cased before any normalisation), an offset value past the per-axis limit collapses to 0.0, clamped values above 1.0 become 1.0, and the curvature parameter equal to 1.0f is the linear (skip) value — anything else applies the extra curve. POV and button fields are only updated on a fully successful poll.
