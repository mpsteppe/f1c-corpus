## sub_60BA90_0060ba90 — drain pending job then release object, mark done flag

**Summary:** If the job object at this+0x1C exists and the done flag 0x20000 is not yet set, it drains the pending counter at this+0x10 (polling the object's vtable slot 0x30 while the pending byte flag is set, decrementing and clearing bit 0x80 each time the poll returns 0), then clears the counter, releases the object via vtable slot 8, nulls the pointer and sets flag 0x20000.

**Written-by note (persistence):**

- this 0x10: written only inside the guarded teardown (decrement per operation, then forced to 0); otherwise untouched.
- this 0x1C: written to 0 only inside the guarded teardown; a poked non-null pointer would be released on the next qualifying call.
- this 0x20: written to 0 only per completed poll operation in the drain loop.

**Guard interpretation:** this[0x1C] == 0 or flag 0x20000 set → nothing happens, returns 0. Otherwise the drain loop runs while this+0x10 > 0; each iteration requires the object non-null, byte 0x80 of this+0x00 set, and the poll (slot 0x30) returning 0 — then bit 0x80 is cleared, this+0x20 = 0 and the counter is decremented (note: if the object is null or the poll keeps returning nonzero, the loop does not progress). After the loop: counter = 0, object released via slot 8, pointer nulled, flag 0x20000 set.
