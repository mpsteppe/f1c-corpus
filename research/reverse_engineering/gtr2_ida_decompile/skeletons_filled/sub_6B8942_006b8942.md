## sub_6B8942_006b8942 — deflate (zlib compression driver)

**Summary:** Full zlib `deflate()` equivalent: validates the stream/flush arguments, writes the 2-byte zlib header on the first call (including preset-dictionary fields), dispatches to the level-specific block encoder through the function table, flushes pending output, handles the flush modes, and on Z_FINISH writes the 4-byte adler32 trailer. Used by the game's PNG writer pipeline.

**Guard interpretation:** Entry guards, all BLOCKING with specific returns: a NULL stream or NULL state or flush > 4 returns -2 (Z_STREAM_ERROR); a NULL next_out, or NULL next_in with nonzero avail_in, or status 666 with flush != 4 also sets strm->msg to the stream-error string and returns -2; zero avail_out sets msg to the buffer-error string and returns -5 (Z_BUF_ERROR). For the table row: when the pending count (0x14) is zero AND there is no input (avail_in == 0) AND the requested flush does not advance beyond the previously recorded flush AND it is not 4 (Z_FINISH), the call is BLOCKED as -5 (Z_BUF_ERROR, msg = buffer-error string). Otherwise when pending != 0 the pending bytes are flushed first; if output space is exhausted the call returns 0 with last_flush set to -1. The encoder path runs only if lookahead != 0, or input remains, or (flush != 0 and status != 666); on Z_FINISH (4) the trailer is written once (guarded by the wrap flag 0x18) and the return is 1 only when nothing is left pending, else 0.
