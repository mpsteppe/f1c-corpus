## sub_54D410_0054d410 — State/mode switcher updating slot pointers and flag bytes

**Summary:** Stores the mode argument into this+8 and switches on it (0, 1, 2, 3; default returns immediately), driving the objects referenced at this+0x20/0x24/0x28 through the sub_5DB5A0/sub_5DB590 helpers and setting the byte at +4 of the slots at this+0x30 and this+0xD0. Modes 2/3 behave like mode 0; mode 1 is the mirror image. Likely a display/activation mode dispatcher (e.g. toggling paired objects on/off).

**Called by:** sub_56AE80 (0056ae80)

| *(this+0xD0) | 0x4 | RW | 0 | Slot flag byte: raised to 1 in mode 0 (only when this+4 is 0), cleared to 0 in modes 1/2/3 |

**Written-by note (persistence):**
- *(this+0x30) 0x4: written conditionally by mode — 0 for modes 0/2/3, 1 for mode 1 when this+4 is 0; an external poke survives until the next conflicting mode transition.
- *(this+0xD0) 0x4: written conditionally by mode — 1 for mode 0 when this+4 is 0, 0 for modes 1/2/3; an external poke survives until the next conflicting mode transition.
- this 0x8: written unconditionally on every call, including the default case; an external poke survives only until the next call.

**Guard conditions:** 
- Switch on a2: case 0 → this+0x20 gets sub_5DB5A0 (if non-zero), 0x30 slot byte ← 0, 0x24/0x28 get sub_5DB590 (each if non-zero), and if this+4 byte == 0 then 0xD0 slot byte ← 1.
- case 1 → this+0x20 gets sub_5DB590 (if non-zero), and if this+4 byte == 0 then 0x30 slot byte ← 1; then 0x24/0x28 get sub_5DB5A0 (if non-zero) and 0xD0 slot byte ← 0.
- cases 2/3 → this+0x20 gets sub_5DB5A0 (if non-zero), 0x30 slot byte ← 0; then same tail as case 1 (0x24/0x28 sub_5DB5A0 if non-zero, 0xD0 slot byte ← 0).
- default (a2 outside 0..3) → return immediately: only this+8 was written; no helper calls or flag updates.
- Every helper call is additionally gated on its object pointer being non-zero; every +4 flag store is gated on its slot pointer being non-zero.
