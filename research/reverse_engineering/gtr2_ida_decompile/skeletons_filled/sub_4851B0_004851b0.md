**Guard conditions:** Message dispatch: `a2 <= 0x110` handles only WM_INITDIALOG (272), WM_DESTROY (2) and WM_CLOSE (16); any other low message returns 0. `a2 > 0x110` handles only WM_COMMAND (273) and the 276 message; anything else returns 0. WM_COMMAND: the control id switch handles 1000..1014, 1026, 1032, 1034, 1042, 1053..1060, 1063, 1065, 1070 — every other id returns v46 (0) unchanged. Per-control literals: 1006-1014 read the checkbox state and set the paired global plus (for 1014) enable controls 1063/1065; 1026 and 1053/1054 require `HIWORD(a3) != 512` to be false; 1055-1059 require `HIWORD(a3) == 512`; 1063/1065 use their own id (1060) for the read and require control 1063's checkbox state (0xF0 message) to decide which of the two globals is zeroed; 1042 requires `HIWORD(a3) == 1` before mapping the selection to lParam and calling sub_47FE30/sub_47FF00; 1034 only continues when the `sub_484CD0()+868` field is non-null. WM_INITDIALOG: the serial-number field is updated only when `RegCreateKeyA` succeeds (and `RegQueryValueExA` is run regardless of its result). WM_CLOSE always posts the quit message.
