## sub_5A4E50_005a4e50 — ProcessExpiryQueues

**Summary:** Per-tick worker routine (thread start routine StartAddress caller): for two timed-entry queues in sequence, takes the queue mutex, walks the entry list decrementing each entry's deadline by the elapsed milliseconds derived from a2 (a2*1000 rounded), and removes entries whose remaining time has reached zero — freeing the node and its optional payload (sub_5A6920 + free) and calling sub_5FDFB0(node, 0) — but only when the auxiliary mutex can be acquired within 1 ms; otherwise the entry is kept for a later pass. Returns 2 (the completed pass count).

**Called by:** StartAddress (005a5ee0)

**Guard interpretation:** When the first dword at this+0x58C is 0, the pass-0 entry walk is BLOCKED (skipped) — no decrements, no removals — though the queue mutex is still released; nonzero PASSES into the walk. During the walk, an entry is removed only when its decremented deadline v11 is <= 0 (v11 >= 0 && old != v22 keeps it) AND the auxiliary mutex at this+0x580 is free (WaitForSingleObject(handle, 1) returns neither 258 nor -1) — if the wait times out (258) or fails (-1) the entry is kept for a later pass. Removal unlinks the entry, decrements the count, frees payload (if flag byte entry+8 set) and node, and calls sub_5FDFB0(entry, 0). The same logic runs for the second queue selected on pass 1 (control at this+0x5A8 and auxiliary structure at this+0x554, not listed in the table).
