## sub_5A4030_005a4030 — ResumeThreadGuarded

**Summary:** Counterpart of sub_5A3F90: under the mutex at this+0xE0 it accumulates a guarded float value (this+0x88 += sub_617F80(this+0x90), then sub_617E70(this+0x90)), releases that mutex, then resumes the worker thread at this+0x8 — if the "suspended by us" flag at this+0x20 is set it runs a bounded ResumeThread retry loop (until the returned suspend count is < 2, up to 50 attempts with Sleep backoff), clears the flag on success, releases the second mutex at this+0x24, and returns 1, or 0 if resuming gave up.

**Written-by note (persistence):**
- this 0x20: Conditionally written — cleared to 0 only after a successful resume (when it was nonzero); set by sub_5A3F90. A poke to 1 triggers a resume attempt; a poke to 0 skips resuming.
- this 0x88: Recalculated/accumulated on every call while the this+0xE0 mutex is held; a poke does not survive the next call.

**Guard conditions:** (1) this+0x8 == 0 (no thread) → early return 1, resume phase skipped. (2) this+0xE0 mutex: if null or WaitForSingleObject returns neither 0 nor 128, v5 is set to 0 and the accumulator update is still executed on that pointer as decompiled (no guard shown). (3) this+0x24 mutex: same null/wait pattern sets v13 = 0; if *v13 is 0 the resume loop is SKIPPED and v11 = 1. (4) Resume loop runs only when *v13 != 0: breaks when ResumeThread returns < 2; retries otherwise; after 50 attempts (v10 >= 50) gives up with v11 = 0 — resuming BLOCKED. On success *v13 is cleared to 0. The this+0x24 mutex is released before returning whenever it is nonzero, and this+0xE0 is released after the accumulator update whenever it is nonzero.
