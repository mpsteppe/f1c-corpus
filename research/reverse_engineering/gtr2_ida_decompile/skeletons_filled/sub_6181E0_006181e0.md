## sub_6181E0_006181e0 — growable_array_assign

**Summary:** Assignment/copy helper for a growable container: reallocates the destination's raw byte buffer (pointer at +0x0, size at +0x4) and its array of 4-byte elements (pointer at +0x8, capacity at +0xC) when they are smaller than the source's, then copies buffer bytes, element bytes (4 × source count at +0x14), and the four trailing dwords (+0x10..+0x1C). Returns `this`.

**Written-by note (persistence):**
- this 0x0: conditional — only rewritten (free + operator new) when destination size (+0x4) is smaller than source size; otherwise buffer contents are qmemcpy'd in place, so an external poke of the pointer survives non-reallocating calls
- this 0x4: conditional — updated only on reallocation when destination size < source size
- this 0x8: conditional — reallocated only when destination capacity (+0xC) is smaller than source's
- this 0xC: conditional — updated only on reallocation when destination capacity < source's
- this 0x10: recalc every call — unconditionally overwritten from a2; an external poke does not survive this call
- this 0x14: recalc every call — unconditionally overwritten from a2
- this 0x18: recalc every call — unconditionally overwritten from a2
- this 0x1C: recalc every call — unconditionally overwritten from a2

**Guard conditions:** Two growth checks, no early return. If `this+0x4 < a2+0x4`, the old buffer is freed and a new `a2+0x4`-byte buffer allocated (+0x4 updated). If `this+0xC < a2+0xC`, the old element array is freed and a new `4 * (a2+0xC)` element array allocated; if `operator new` fails, the destination pointer +0x8 is set to 0 (no error path) and +0xC is still updated. When the destination is large enough, the buffers are reused in place and both memcpy paths always execute.
