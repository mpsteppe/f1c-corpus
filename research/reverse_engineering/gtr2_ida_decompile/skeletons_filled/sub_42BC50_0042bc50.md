**Guard interpretation:** `sub_42AED0` returning 0 blocks the whole setup: the failure path runs sub_4E5FC0(&dword_B6E4D0,5), clears byte_B699B4/byte_B699BC, sets dword_B6E4D8 to 100/200/300 based on this+0x400 (0/1/2) and sets byte_B660D0 = 1. On success the branch depends on the derived flag this+0x1F0: value 1 takes the "auto" path (timers zeroed, sub_583170, and the sub_412EB0/sub_412520 dispatch when the state is still 5), while value 0 takes the track path (sub_57F840, sub_53E6A0, this+0x418 = 1, sub_412EB0(&dword_91BF20,5,1)). The this+0x400 byte never gates the load itself; it only selects the flag passed to sub_53F190 and the fallback value on failure. Registers/flags `!= 1`/`== 1`/`== 2` on this+0x400 are the only literals tested.
