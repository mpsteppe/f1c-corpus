## sub_64645D_0064645d — Stream flush (write out buffered data)

**Summary:** Flushes the stream object's staging buffer: in buffered-file mode it writes any pending bytes to the Win32 file HANDLE and moves the count into the running total; in the other modes it does nothing. Returns 0 on success or 0x80004005 (E_FAIL) on WriteFile failure.

**Called by:** sub_6493C0 (006493c0), sub_64A702 (0064a702)

**Struct fields accessed:**

| Base | Offset | R/W | Init (literal → value) | Purpose |
|------|--------|-----|------------------------|---------|
| this | 0x0 | R | — | Win32 file HANDLE passed to WriteFile. |
| this | 0x10 | R | — | Mode selector: 0 = nothing, 1 = buffered file (flush), 2 = memory mode (nothing). |
| this | 0x18 | R | — | Pointer to the staging buffer holding pending bytes. |
| this | 0x1C | RW | 0 | Fill level (pending byte count); read as the flush length and reset to 0 after a successful write. |
| this | 0x20 | RW | — | Running total of bytes written; incremented by the flushed fill count. |

**Written-by note (persistence):**
- this 0x1C: written only when mode 1 and fill ≠ 0 (reset to 0 after the flush); an external poke survives until the next flush or write call.
- this 0x20: only incremented on the flush-by-fill amount, never recomputed from scratch; an external poke survives until the next flush/write.

**Guard conditions:** Mode field this+0x10: if 0 → return 0 (no-op). If 1 → if fill (0x1C) is 0, nothing happens and 0 is returned; otherwise WriteFile to the handle with fill bytes; WriteFile false → return -2147467259 (0x80004005, E_FAIL); on success total (0x20) += fill and fill = 0.
