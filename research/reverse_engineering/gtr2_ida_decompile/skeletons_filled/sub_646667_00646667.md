## sub_646667_00646667 — Texture block parse & decode (palette / RLE / masked-to-float)

**Summary:** Parses an in-memory texture description block (header + optional palette + pixel payload) and fills the surface object: recognizes bit depth, compression and channel masks into an internal format id, optionally builds a 256-entry RGBA palette, allocates the destination buffer and decodes raw, RLE or bit-packed pixels (including masked integer formats expanded to float RGBA). Returns 0 on success, 0x80004005 (E_FAIL) on malformed input, 0x8007000E (E_OUTOFMEMORY) when an allocation fails.

**Called by:** sub_6493EF (006493ef), sub_64A450 (0064a450)

**Written-by note (persistence):**
- this 0x0: written once per successful parse from the format recognition result; a poke survives until the next parse.
- this 0x4: written once per parse (source pointer or fresh allocation); a poke survives until the next parse and can orphan the previous buffer.
- this 0x8: written only in the palette branch; otherwise untouched, so a poke survives until a later palettized parse.
- this 0xC: rewritten on every successful parse; pokes do not survive a parse.
- this 0x10: rewritten on every successful parse; pokes do not survive a parse.
- this 0x14: unconditionally set to 1 on every successful parse; pokes do not survive.
- this 0x30: recomputed on every successful parse; pokes do not survive.
- this 0x34: unconditionally reset to 0 on every successful parse; pokes do not survive.
- this 0x38: set to 0 or 1 on every decode; pokes survive only until the next parse.
- this 0x3C: set to 1 only in the palette branch; not touched on non-palettized parses, so a poke would otherwise persist.

**Guard conditions (deterministic — field vs literal):**

| Base | Offset | Test | Value | Field / meaning |
|------|--------|------|-------|-----------------|
| this | 0x40 | == | 0 | Mode gate: when 0 the function stops after storing format/size metadata (no palette, no allocation, pixel pointer untouched); nonzero continues into palette creation and pixel decoding. |

**Guard interpretation:** For this+0x40: == 0 PASSES only as far as the metadata stores and then returns 0 early; ≠ 0 PASSES into the full decode (palette for format 41, direct-reference fast path, or allocation + RLE/bit-unpack/raw/float conversion). Input-side gates (not this-relative): a3 < 4 → E_FAIL; the header's first dword must not exceed a3 → E_FAIL; a 12-byte header is normalized into a synthetic larger descriptor, any other size < 0x28 → E_FAIL; the computed pixel-data offset (header + palette bytes) must be ≤ a3 and the word at header +12 must equal 1 → else E_FAIL; the compression dword at +16 must be 0/1/2, or exactly 3 only when the header is ≥ 0x34 → else E_FAIL; unsupported bit depths at +14 → E_FAIL; unrecognized channel-mask combinations fall back to format id 116 (float expansion) rather than failing. Successful passes write this+0x0 (format), +0xC (width), +0x10 (height), +0x30 (pitch), +0x14 = 1, +0x34 = 0, and set +0x4/+0x8/+0x38/+0x3C depending on the path chosen.
