## sub_457A50_00457a50 — VehiclePhysicsSubstep (wheel/suspension integration step)

**Summary:** Runs one physics integration pass for a vehicle: executes the sub-stepped body integration (with timestep clamping and fallback re-steps), integrates the four wheel spin angles (wrapped with `fmod`), updates the four suspension/damper models, checks suspension travel against a bump threshold, and re-aligns the four wheel contact objects (position, 3x4 orientation and state copied from the track contact matrix). Guarded by the sim-rate flag `dbl_903EC8 == 1.0` or `byte_B6F118 == 0`.

**Guard conditions:** The routine body is entered only when `dbl_903EC8 == 1.0` or `byte_B6F118 == 0`. Timestep logic: when the integrated value `v20 < 1.0` and `dword_B6FC28` is set with `v20 != this+136`, the step is snapped to a multiple of the base timestep; when still `< 1.0` and `<= 0.5`, an alternate step (`v22 * 0.999 * v20`) is used, clamped up to a minimum of 0.000003814697265625 (2^-18), followed by a fallback re-step. The integration loop breaks when `v34 <= v18`. The bump event fires when a suspension's travel ratio `(current - base)/(ref - base) < 0.33` (checked once per wheel, 4 iterations). The contact re-alignment runs only when the wheel's contact pointer is non-null AND the wheel flag byte at this+0x490 is zero; the transform is applied when either the forward dot product `< 0.5` or the absolute side product `> 0.7`. The final cleanup call only happens when `HIDWORD(v21) != 512`.
