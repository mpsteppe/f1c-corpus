## sub_5F11A0_005f11a0 — Nested-array container destructor

**Summary:** Frees a container with two possible layouts selected by its flag dword: bit1 destroys each 12-byte row's 12-byte sub-array (per-element pointers at +4 freed first) then the this+0x28 row array; bit0 destroys each 44-byte element's 32-byte sub-array at +40 then the this+0x20 element array. Every heap array is walked by the MSVC array destructor iterator (element count from the allocation cookie) and then freed. Cleanup/destructor helper.

**Called by:** sub_5F1360 (005f1360)

**Struct fields accessed:**

| Base | Offset | R/W | Init (literal → value) | Purpose |
|------|--------|-----|------------------------|---------|
| this | 0x0 | R | — | Layout flags; bit1 (2) selects the 12-byte-element layout, bit0 (1) the 44-byte layout, neither → no work |
| this | 0x1C | R | — | Element count of the 44-byte-element array (this+0x20) |
| this | 0x20 | R | — | Base pointer of the 44-byte-element array (layout bit0) |
| this | 0x24 | R | — | Element count of the 12-byte-element array (this+0x28) |
| this | 0x28 | R | — | Base pointer of the 12-byte-element array (layout bit1) |

**Guard conditions (deterministic — field vs literal):**

| Base | Offset | Test | Value | Field / meaning |
|------|--------|------|-------|-----------------|
| this | 0x1C | > | 0 | 44-byte-layout element count (this+0x1C) — only a positive count enters the per-element teardown loop |
| this | 0x24 | > | 0 | 12-byte-layout row count (this+0x24) — only a positive count enters the per-row teardown loop |

**Guard interpretation:** Layout selection: `*this & 2` set → the 12-byte layout path runs, and `else if (*this & 1)` set → the 44-byte layout path runs; if neither bit is set the function does nothing and returns 0. In the bit1 path, per-row processing runs only while `this+0x24 > 0`; each row frees its per-element pointers only when the row's element count (`row+4`) is positive, and the row's sub-array destructor/free runs only when the row's pointer (`row+8`) is non-null; the top array is destroyed/freed when `this+0x28` is non-null. In the bit0 path, per-element processing runs only while `this+0x1C > 0`; each element's 32-byte sub-array at `element+40` is destroyed/freed only when that pointer is non-null; the top array is destroyed/freed when `this+0x20` is non-null. Null pointers therefore PASS through silently rather than being freed.
