## sub_405680_00405680 — std::string-like reallocate-and-copy (assign buffer)

**Summary:** Replaces the contents of a string-like object: computes a new capacity (minimum `a2|0xF`, with 1.5x growth if the current capacity exceeds 3x the requested size), allocates a new heap buffer, copies `a3` bytes from the old storage and null-terminates. Empty/short strings keep using the inline buffer at this+4; heap-allocated storage is freed with j__free. Runs inside an SEH try-scope (loc_405713 / SEH_405680).

**Called by:** (none static — top-level or indirect-only)

**Struct fields accessed:**

| Base | Offset | R/W | Init (literal → value) | Purpose |
|------|--------|-----|------------------------|---------|
| this | 0x4 | RW | 0 | String storage pointer / inline buffer start; first byte zeroed as the null terminator after the copy |
| this | 0x14 | RW | — | String length (set to a3 bytes copied) |
| this | 0x18 | RW | — | String capacity (v3, decides inline vs heap storage: < 0x10 = inline) |

**Written-by note (persistence):**
- this 0x4: written on every call (pointer to the new buffer for heap strings, inline storage address otherwise) — an external poke is overwritten on the next call and can make the old buffer leak/dangle
- this 0x14: written on every call from a3 (copied byte count) — external poke overwritten on next call
- this 0x18: written on every call from the recomputed capacity — external poke overwritten on next call

**Guard conditions (deterministic — field vs literal):**

| Base | Offset | Test | Value | Field / meaning |
|------|--------|------|-------|-----------------|
| this | 0x18 | < | 16 | Capacity below MSVC small-string limit → old data lives in the inline buffer, source = this+4 |
| this | 0x18 | >= | 16 | Capacity at/above limit → buffer pointer at this+4 is heap storage: its target is copied from, then freed with j__free |

**Guard interpretation:** Capacity < 16 PASSES the inline-buffer path (copy source = this+4, no free); capacity >= 16 PASSES the heap path (copy source = *(this+4), and the old block is freed after the copy). After the update, the returned pointer is the inline buffer when the new capacity is < 16, otherwise the freshly allocated heap buffer; `result[v8] = 0` always writes the terminating null.
