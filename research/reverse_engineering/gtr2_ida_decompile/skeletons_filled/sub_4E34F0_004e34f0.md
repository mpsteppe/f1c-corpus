## sub_4E34F0_004e34f0 — load texture info, create power-of-two render texture, blit and store UV scales

**Summary:** Texture-loading routine: releases any previous handle, looks up texture info by name (object string or WindowName fallback) through sub_5E7E80, computes power-of-two dimensions and the cropped source rectangle from (a2,a3,a4,a5), creates a render texture via sub_5E47E0, blits the source region into it with sub_5E7540, and stores the resulting UV scales (0xC/0x10) and dimensions (0x14/0x18). Returns 1 on success, 0 on failure.

**Called by:** (none static — top-level or indirect-only)

**Written-by note (persistence):**
- this 0x8: Written conditionally each call — zeroed at entry when a previous handle existed, overwritten by the creation call, zeroed again on creation failure; not per-frame — an external poke survives only when neither path writes it (e.g., lookup fails early).
- this 0xC: Written only in the success branch after creation/blit; an external poke survives until a later successful call.
- this 0x10: Written only in the success branch after creation/blit; an external poke survives until a later successful call.
- this 0x14: Written only in the success branch (from info+4); an external poke survives until a later successful call.
- this 0x18: Written only in the success branch (from info+8); an external poke survives until a later successful call.

**Guard interpretation:** If the name pointer at this+0x0 is ZERO, the object's string is not used — WindowName is substituted; if NON-ZERO, the object's name is used. Other branches from the code: an entry guard releases the stale handle only when this+0x8 is non-null (and zeroes it); the main body runs only when the lookup returns 0 AND v22 is non-null; crop deltas a4/a5 are applied only when strictly between 0 and the computed extent (otherwise ignored); creation failure (nonzero return or null handle) releases the new handle and returns 0, while success blits the rectangle, stores the UV scales/dimensions and returns 1; the info object is always released when the main body executes.
