## sub_45EB50_0045eb50 — DirectInput poll: update mapped key states from device buttons

**Summary:** Per-frame input update. Reads the DirectInput device at this+0x4 either via buffered device data (when the mode flag this[0] is not 2) or via a 256-byte GetDeviceState snapshot (when this[0]==2, with re-Acquire retry on input-lost/not-acquired), then translates button state into the object's mapped key arrays: updates per-key float timers at 0x484 with the frame delta a2 (or the -0.5/-0.1 constants at 0xC80/0xC84), maintains per-button state bytes at 0x381, and appends (modifier flags | button index) event words into the event list at 0xC8C.

**Written-by note (persistence):**
- this 0x381: rewritten for every button on every poll (values 0/1/3); an external poke is lost at the next poll.
- this 0x484: entries overwritten during the mapping pass every poll (delta added or constant stored); poke survives only until the next poll touches that index.
- this 0xC88: unconditionally zeroed near entry and then incremented; a poke never survives a poll call.
- this 0xC8C: appended-to (indexed by the event count) only while new events are recorded; a poke survives until an event is recorded at that slot on a later poll.

**Guard interpretation:** Entry requires this[1]!=0 and byte_75B2B9!=0, else the function does nothing. With this[0]!=2 it reads queued events via GetDeviceData; if either the flush or the read fails it returns without processing. With this[0]==2 it takes a GetDeviceState snapshot; on DIERR_INPUTLOST/DIERR_NOTACQUIRED it calls Acquire and retries once, and any remaining error returns without processing. After the state is obtained, the per-button loop processes each button whose raw state bit is set or whose v7[256] still compares above dbl_FB1D20. Finally, this[0xC88]>0 triggers the fix-up pass over recorded event words (scancode switch, toggle bit 15 for letter keys); when it is 0 that pass is skipped and the function returns — nothing else is blocked or gated by these two fields.
