## sub_60A680_0060a680 — Settings reset/initializer with manager notifications

**Summary:** Resets this settings object: clears the six value slots (0xCC–0xE4), preloads -1 sentinels at 0xF4/0xF8 and 0xFC, stores the incoming handle a2 at 0xF0, then programs slot 1 to 4 via sub_609B00, sets slot 2 to 2 and slot 3 to 1 with direct manager notifications (gated by the enable byte at 0xEC), sets 0xF4 to 4, calls the thunk sub_60A000(2), and finally notifies channel 11 with the handle.

**Written-by note (persistence):**
- this 0xCC: unconditional clear in the reset body, then rewritten to 4 via sub_609B00; a poke is overwritten on the next reset.
- this 0xD0: unconditional write in the reset body; a poke is overwritten on the next reset.
- this 0xD4: unconditional write in the reset body; a poke is overwritten on the next reset.
- this 0xDC: unconditional clear in the reset body; a poke is overwritten on the next reset.
- this 0xE0: unconditional clear in the reset body; a poke is overwritten on the next reset.
- this 0xE4: unconditional clear in the reset body; a poke is overwritten on the next reset.
- this 0xF0: unconditional write from a2 on each reset; a poke is overwritten on the next reset.
- this 0xF4: written twice per reset (sentinel -1, then 4); a poke is overwritten on the next reset.
- this 0xF8: unconditional sentinel write per reset; a poke is overwritten on the next reset.
- this 0xFC: written to -1 and then possibly to the handle; a poke is overwritten on the next reset.

**Guard conditions (deterministic — field vs literal):**

| Base | Offset | Test | Value | Field / meaning |
|------|--------|------|-------|-----------------|

**Guard interpretation:** The resets of all slots and sentinels are unconditional. For slot 2 (0xD0) and slot 3 (0xD4), the `!= 2` / `!= 1` checks compare against the freshly cleared value 0, so both PASS in practice — the slots are written 2 and 1, and the manager notification at +268 fires only when the enable byte at 0xEC is NONZERO (the `== 0` test means "disabled"). The final channel 11 notification PASSES only when the handle a2 is not -1 and differs from the cached value at 0xFC; on pass, 0xFC is updated to the handle.
