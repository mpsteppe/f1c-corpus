# VehiclePhysics

Scope: `vehicle_physics`  
Trust: `DERIVED`

Three functions. UpdateSuspensionAndWheelPhysics (0x004E5F60) is the per-frame vehicle physics update owned by the vehicle object (this): it copies and adjusts the four wheel contact-patch positions, recomputes weight distribution from the car-setup argument a2, rebuilds per-wheel suspension/tire state (temperatures, loads, spring/damper split), computes anti-roll-bar mixing and drivetrain/mass parameters, runs a 13-point contact-position transform (bitmask-driven tweaks, bounding-radius tracking), evaluates six polynomial/tire-force helper models, sums the force vector, applies session (a3) offsets to tracked contact points, fills a 13-point particle buffer, writes wheel output positions, and returns an advanced pointer into the session block. SetWheelForceParameters (0x004F1BA0) is a conditional wheel force/torque setter on the same vehicle object: when the physics-mode flag at +0x32BC is set it stores four per-wheel parameters into the per-wheel blocks (stride 248, force field at block offset 0x24), otherwise it applies them directly to a rigid body via an inertia-tensor helper; called from pit-stop progress (0x004A68B0). TireModelDataInit (0x004F34E0) is a bulk constructor for a distinct per-vehicle tire model data object (ABI lead Tire_Model_Data_Init, LEGACY): handle sentinels (0 and -1), compound count 15, friction/camber/slip coefficient seeding, multiple zero-init sub-structures and zero runs, four 66-dword physics-default sub-structs, and a config-path string copy through StringCopyWithBufferRealloc on global 0x005EA438.

## Function roles

- `0x004E5F60` **Vehicle** — Per-frame vehicle physics update: contact-patch position copy/adjust/bias, weight-distribution recompute, per-wheel suspension/tire state rebuild, anti-roll-bar and drivetrain/mass parameter computation, 13-point contact-position transform with bitmask tweaks and bounding-radius tracking, force-model summation and smoothing, session-offset application to tracked contact points, particle buffer fill, wheel output publish, session-block pointer advance.
- `0x004F1BA0` **Vehicle** — Conditional wheel force/torque parameter setter: when the physics-mode flag at +0x32BC is non-zero stores four per-wheel parameters into the wheel-force fields (per-wheel blocks at +0x3664/+0x375C/+0x3854/+0x394C, stride 248); otherwise applies them directly as force/torque to a rigid body via the inertia-tensor helper using global dbl_7C7428. Used during pit-stop wheel operations (caller 0x004A68B0).
- `0x004F34E0` **TireModelData** — Bulk constructor/initializer for the per-vehicle tire model data object: handle sentinels (primary 0, others -1) and compound count, friction/camber/slip coefficient seeding, physics-constant and per-compound coefficient seeding, multiple zero-init sub-structures and zero runs, four 66-dword physics-default sub-structs in a fixed loop, sub-constructor call, and config-path string copy through StringCopyWithBufferRealloc on global 0x005EA438. ABI lead name Tire_Model_Data_Init (LEGACY).

## Compatibility contracts

- **PerWheelStateBlockLayout** — Four per-wheel state blocks of 248-byte stride on the vehicle object (base 0x35AC). The wheel-force field sits at block-relative offset 0x24 (absolute 0x3664/0x375C/0x3854/0x394C): SetWheelForceParameters stores four per-wheel force parameters there, and the per-frame update initializes and reads the same block layout. A replacement must preserve the stride and the block-relative offsets.
- **ContactPointOutputBuffer** — The 13-point contact-position output buffer at vehicle+0x3AB8 (stride 12 bytes) is computed each frame, copied into the 28-byte-stride wheel output array at +0x1078, and consumed by the vertex/particle buffer allocation; the bounding radius is tracked at +0x3B6C with +0x3B70 = +0x3B6C + 0.1. A replacement must produce all 13 points and publish them to +0x1078.
- **PhysicsModeGate** — The flag at vehicle+0x32BC gates two paths: non-zero enables the per-frame suspension body-offset override and the wheel-force field-storage path in SetWheelForceParameters; zero disables the override and routes the same four parameters to a direct rigid-body force/torque application using the dbl_7C7428 scalar as the inertia-tensor argument. A replacement must preserve this gate's effect on both consumers.
- **SessionWheelRecordReturnPointer** — UpdateSuspensionAndWheelPhysics returns a pointer advanced through four per-wheel 33-double records starting at session+5200 (plus the axis blocks at session+5336/+5864). The caller 0x004E45B0 (LargeConfigFunctionWithPhysicsConstants) uses the returned advanced pointer; a replacement must reproduce the pointer arithmetic.
- **TireModelDataHandleConvention** — The tire model data object's header uses handle sentinels (primary field 0, other handle slots -1), a compound count of 15, and alternating sentinel/zero handle pairs. Its config path is passed through StringCopyWithBufferRealloc from the global buffer 0x005EA438. A replacement must preserve the handle convention and the config-loading call.

## Unresolved

- The a2 (car setup) and a3 (session/track) argument structs of UpdateSuspensionAndWheelPhysics are not described by the packet; their field semantics are inferred from usage and their offsets appear only in the raw source's decimal spelling.
- The a3+60 bitmask (bits 1/2/4/8) selects per-point visibility and geometry adjustments in the 13-point contact loop; the exact meaning of each bit is inferred from usage, not confirmed.
- 31 physics globals reported by the packet (read-only constant families at 0x0059E, 0x005AC, 0x005AD) are not visible in the recovered raw source; they are likely consumed inside the helper calls (polynomial evaluators, tire-force models) rather than directly here.
- The return value of UpdateSuspensionAndWheelPhysics is a pointer advanced through the per-wheel session record block (a3+5200, stride 33 doubles); the caller's use of that pointer is unknown beyond the contract entry.
- The content semantics of the session block copied from a3+6128 into the vehicle +0x3D58 region are not recoverable from this function's evidence alone; the region is also later overwritten by the computed body Y position.
- The transform performed by sub_4DD7C0 (direction-vector projection) is inferred from its call sites; its exact matrix/geometry semantics are unknown.
- dbl_7C7428 is the inertia-tensor argument to the direct-apply helper in SetWheelForceParameters; its exact meaning (single inertia value vs struct base) is unconfirmed.
- The four wheel-force fields at +0x3664/+0x375C/+0x3854/+0x394C are recalculated every frame elsewhere, so values stored by SetWheelForceParameters are transient (persistence verdict: recalced).
- The direct-apply helper identity in SetWheelForceParameters is provided only by name in existing analysis; no callee address evidence is in the packet.
- Contradiction: vehicle+0x3510/+0x3514 are written both as the vehicle mass / mass-with-payload (session a3+64) and as the wheel-block header anti-roll mixing factors; the packet does not reconcile the two uses.
- Contradiction: vehicle+0xCC8 and +0xD0C are described both as tracked-point flags and as front/rear wing transform presence flags; the dual role is unresolved.
- TireModelData owner identity is not established by the packet (UnknownObject); the ABI lead Tire_Model_Data_Init is LEGACY trust only.
- The sub-calls of TireModelDataInit (ZeroInit, sub_4F31F0, ZeroInit16ElementArray, PhysicsDefaultsInitializer, ConstructorZeroInitSubCalls) have named identities but their internal layouts are outside this packet.
- StringCopyWithBufferRealloc(byte_5EA438) passes the global buffer read-only; whether byte_5EA438 is an input path string or a pre-allocated destination buffer is unconfirmed.
- TireModelData's offset space (0x0..+0x13CC) numerically overlaps the Vehicle offset space; the two bases are kept separate per the evidence, but embedding the tire model data within a larger vehicle allocation is possible and unproven.
