# GenericRuntimeObjects

Scope: `generic_runtime_objects`  
Trust: `DERIVED`

Reconstructs the generic runtime object layer from 22 validated functions spanning three evidence families. One DERIVED class SlabBuddyAllocator (0x0059491A initialize, 0x00594AB4 page-trim, 0x00594C12 allocate) models the pool/slab allocator with the off_5E7968/off_5E796C context linked list, the off_5E9988 round-robin cursor, 8-byte free descriptors carved by sub_594E1A, and VirtualAlloc-committed 4KB pages split into chained blocks. A second GUESS class SubbinBuddyAllocator (0x00594624) covers the subbin free path, whose object layout (region base at +0xC, subbin data base at +0x10, 516-byte subbin stride, aggregate size-class bitmaps at +0/+4) does not match the pool-context layout, so the two are kept as separate classes. A DERIVED CRTFileHandleTable (0x00595924/0x005959A0/0x00595A1F/0x00595AC0/0x00595F11/0x00595F82) models the 36-byte-stride file-descriptor records (handle at +0, flags at +4, embedded CRITICAL_SECTION at +12). A GUESS PoolRegionFreeSpaceTable (0x00594F3E) tracks per-region free sizes through an 8-byte-stride entry table. Eleven CRT support functions (string parse delegation, float digit formatting, single-character ANSI<->wide conversion, strtod-style float parsing, character-type retrieval, 64-bit left shift, math-error dispatch, runtime-error exit, format-buffer forwarder, byte-buffer push) have unknown owners and are left unowned. One GUESS FloatParseStateMachine documents the strtod jump-table parse phases; the exact state-id mapping (0-11) is not fully recoverable.

## Function roles

- `0x00594624` **SubbinBuddyAllocator** — Releases a memory block back into the subbin/buddy allocator object a1: aligns the requested size to 16 bytes, derives the subbin selector from (block - a1[3]) >> 15, reads the block header at a2-4 (slot count and total span), then splits an oversized free block into an allocated part plus a free remainder or, when already free, coalesces with its buddy. The remainder is re-inserted into its size-class free list while the aggregate bitmaps a1[0] (classes below 0x20) and a1[1] (classes 0x20-0x3F) and the per-subbin bitmap arrays are updated. Returns 1 on success, 0 when the block is in use or the request exceeds the total span. Invoked from sub_58B5D4.
- `0x0059491A` **SlabBuddyAllocator** — Initializes a pool/slab allocator context: uses the static pool at off_5E7968 when dword_5E7978 == -1, otherwise HeapAlloc(hHeap, 0, 0x2020) a context; on failure returns 0. Reserves a 0x400000-byte region with VirtualAlloc, commits 0x10000 bytes, links the context into the off_5E7968/off_5E796C free list (self-link in the static-pool case, insertion otherwise), fills a 1024-entry x 2-word free-list table, zeroes the committed region via sub_58BB10, and walks 1024-byte slabs setting header words. Returns the context pointer.
- `0x00594AB4` **SlabBuddyAllocator** — Walks the allocator-context linked list (head off_5E796C) and decommits free pages (page-table entries holding 240) via VirtualFree(MEM_DECOMMIT) up to a remaining page budget a1. Each successful decommit marks the entry -1, decrements the live page counter dword_8D41B8, and lowers the context lowest-free pointer v1[3]. When one context's entire page table becomes -1 (all 1024 pages free) the context is destroyed via sub_594A5E. Void return.
- `0x00594C12` **SlabBuddyAllocator** — Public memory allocation. Round-robins through the linked list of allocator contexts seeded by off_5E9988, scanning each context's 8-byte free descriptors and carving a block with sub_594E1A; the descriptor start is shrunk and the cursor global updated on success. When no existing context fits, falls back to the static pool list headed by off_5E7968: commits pages with VirtualAlloc, zeroes them via sub_58BB10, and splits them into chained 4KB blocks recorded in the pool's descriptor table. When every pool is exhausted, creates a new allocator via initializeSlabBuddyAllocator and returns its first 256-byte block (page base + 256). Returns the allocated pointer or 0 on failure. Called by sub_58A973, sub_58AB58 and sub_58B5D4.
- `0x00594F3E` **PoolRegionFreeSpaceTable** — Resizes a byte buffer a3 (whose current size is stored at *a3) to a4 while maintaining a per-region free-size counter in the entry table owned by a1. v5 selects the 8-byte-stride entry at a1+24 whose index is ((a2 - *(a1+16)) >> 12). On shrink clamps the size, adds the freed delta to *v5, marks v5[1] = 241 and returns 1. On grow verifies the region from the old end to the new end v6 is all zeroes, commits the new size, updates the descriptor a2, adjusts the entry counter and returns 1. Returns 0 on the fallthrough paths. Invoked by sub_58B5D4.
- `0x00595524` **UnknownObject** — Trivial __cdecl forwarder that delegates to sub_5953B8(a1, a2, dword_5E99A0), forwarding the two caller arguments plus the global context pointer dword_5E99A0 as a third argument, and returns the callee's result unchanged. Called by EncodingLocaleDetectionFromParseResult (0x0058E12E) and BufferFormatHelper (0x00595550).
- `0x005955AA` **UnknownObject** — CRT digit-string formatter for number-to-string conversion. Writes a leading '0' (48) at a1[0], copies a2 digit characters from the stream at a3+12 (substituting '0' for a zero byte), NUL-terminates the result, applies round-up with carry propagation when the next unconsumed digit is >= '5', then skips a leading '0' via sub_58B130 when the leading digit did not round up; on carry overflow into the leading digit it increments the counter at a3+4 and returns the pointer past it. Callers: FloatToStringWithSignWidth, IntToStringWithSignPositionDraw, UtilityFunction_bfec.
- `0x00595733` **UnknownObject** — Thin runtime-error exit wrapper: calls CRTAmsgExit (0x0058A2A6) with the argument 2u and returns its result. No local state, no guards, no fields.
- `0x00595924` **CRTFileHandleTable** — CRT file-descriptor handle assignment. If descriptor index a1 is in range (a1 < uNumber) and its slot in the 36-byte-stride descriptor table (dword_8D4920[a1>>5] + 36*(a1&0x1F)) is empty (== -1), optionally binds the console standard handle matching a1 when dword_5E65B4 == 1, stores the supplied handle in the slot and returns 0; otherwise stores error 9 in the TLS error slot via TLSOffsetGetter, clears the extended error slot via TLSOffsetGetter_afd8 and returns -1.
- `0x005959A0` **CRTFileHandleTable** — CRT file-descriptor handle release, structural twin of CRTFileHandleAssign. If descriptor index a1 is in range, the flag byte at slot offset 4 has bit 0 set (slot in use), and the slot dword is not -1, optionally clears the console standard handle matching a1 when dword_5E65B4 == 1, resets the slot dword to -1 and returns 0; otherwise stores error 9 in the TLS error slot, clears the extended error slot and returns -1. Called by HandleCloseWithErrorReporting.
- `0x00595A1F` **CRTFileHandleTable** — Returns the raw Windows handle for a CRT file descriptor entry. Guards a1 against the open file count uNumber, locates the entry as dword_8D4920[a1>>5] + 36*(a1&0x1F), and returns the handle dword at the entry base when the open flag (bit 0 of the byte at entry+4) is set. On an out-of-range index or a closed entry writes TLS error 9 via TLSOffsetGetter, clears the extended error slot via TLSOffsetGetter_afd8 and returns -1. Called by HandleCloseWithErrorReporting, FileSeekViaSetFilePointer, sub_592891, FilePointerSeekWithErrorHandling, sub_59797B and sub_59B650.
- `0x00595AC0` **CRTFileHandleTable** — Releases the per-file critical section for file index a1. The section is embedded at record offset +12 of a 36-byte record inside the bucket dword_8D4920[a1>>5], with the entry selected by a1 & 0x1F, and is released via LeaveCriticalSection. Called from nine file-I/O sites as the common leave path after file operations.
- `0x00595AE2` **UnknownObject** — Forwarding wrapper (cdecl): calls sub_595AF9 with lpFileName, a2, the fixed size argument 64, and a3, then returns its result. The third argument is pinned to 64, matching a 0x40-byte format-buffer size. Used by ShortComputation_5050, sub_4069F0 and RegistryKeyQuery.
- `0x00595F11` **CRTFileHandleTable** — Checked file-handle seek wrapper. If a1 is a valid open file index (a1 below the uNumber count and the record's flag byte at offset 4 of the per-file record having bit 0 set), it enters the per-file critical section via CriticalSectionEnterWithLazyInit, performs a seek via FilePointerSeekWithErrorHandling, leaves the critical section via FileCriticalSectionLeave and returns the seek result. Otherwise it writes error code 9 into the primary TLS slot, zeroes the secondary TLS slot and returns -1.
- `0x00595F82` **CRTFileHandleTable** — Wraps a file seek on a handle resolved from index a1 via CRTFileHandleRead. On handle failure stores error code 9 through TLSOffsetGetter and returns -1. Performs a 64-bit SetFilePointer seek: high 32 bits passed as a3, low 32 bits assigned from the return value; on a -1 low dword with non-zero GetLastError routes the error through ErrorIDLookupTable and returns -1. On success clears bit 2 of the file-handle-table flag byte at record+4 and returns the full 64-bit position. Invoked by sub_595F11.
- `0x00596089` **UnknownObject** — Converts a single wide character (WideCharStr) into multi-byte form, the wide-to-ANSI mirror of the single-character conversion layer. Returns 0 when the output buffer lpMultiByteStr is NULL. When no locale is set (dword_8D3F38 == 0) and the character fits in one byte (WideCharStr <= 0xFF) it writes the truncation directly into the buffer and returns 1. Otherwise calls WideCharToMultiByte(CodePage, 0x220u, ...) and returns the byte count written, or -1 with TLS error 42 via TLSOffsetGetter when conversion fails or a default (replacement) character was used. Called by sub_596030.
- `0x00596175` **UnknownObject** — MSVCRT-style math error handler dispatcher. Reads the error type code at *(DWORD*)a2 and maps types 1/5 to action 8, type 2 to 4, type 3 to 17, type 4 to 18, type 6 to a reset (*(DWORD*)a2 = 1, handler skipped) and type 7 to 16; type 8 falls through with no handler. When sub_5919DA returns nonzero the handler is suppressed; otherwise sub_591727 builds the error-handler argument array. Afterwards the FPU control word is restored via ReturnFPUControlWord and SetErrorCodeBasedOnInputRange(*(DWORD*)a2) is returned when the error type is 8, the FPE exception flag dword_5E9AD0 is set, or StubReturning0() returns NULL. Called from MSVCCRTMathErrorHandler and sub_59070A.
- `0x00596245` **UnknownObject** — CRT strtod-style state-machine float parser. Skips leading whitespace, then parses an optional sign, integer and fraction digit runs, and an optional decimal exponent, dispatching states through the jump table jpt_5962A8. Digit classification uses the char-type table off_5E69C8 (bit 4) or CharacterEncodingConvertViaLookupTableFallback when cbMultiByte exceeds 1; byte_5E6BD8 is the decimal separator. Collected digits fill a 25-entry buffer (cap 0x19); sub_597621 packs the digit buffer into a 96-bit value and BitPackedDataDecodeViaLookupTable applies the exponent. The 96-bit result is written to the output (low word at +0, mid dword at +2, high dword at +6, sign-or-exponent word at +10), the end-of-parse pointer is stored to *a2, and a classification code is returned (4 no digits, 2 overflow, 1 underflow, 0 valid). Called by EncodingLocaleDetectionFromParseResult, BufferFormatHelper and StringParseWithFormat.
- `0x00596773` **UnknownObject** — Converts a single multi-byte character into a wide character, the one-character MB_ERR_INVALID_CHARS path of the ANSI layer. Returns 0 when the input buffer is NULL or the max-byte count a3 is zero; writes a NUL wide char and returns 0 when the first byte is NUL. When no locale is set (dword_8D3F38 == 0) it assigns the byte directly as the wide char and returns 1. Otherwise it consults the character-type table off_5E69C8 for a lead byte: single-byte characters go through MultiByteToWideChar with length 1, while lead bytes use the cbMultiByte sequence length when a3 allows it. On conversion failure stores TLS error 42 via TLSOffsetGetter and returns -1. Returns the number of bytes consumed on success. Called by sub_596716.
- `0x00596840` **UnknownObject** — CRT ___allshl 64-bit left-shift helper. Shifts the 64-bit value a1 (edx:eax) left by the count a2 (cl): a count of at least 0x40 yields a zero result, a count in [0x20, 0x40) zeroes the low 32 bits of the result, and a smaller count returns a1 shifted by (a2 & 0x1F). Invoked by sub_58E4D2 as the 64-bit shift helper.
- `0x00596888` **UnknownObject** — Byte-push writer over an allocator-managed buffer descriptor a2 (current position, element count, allocation end, flag word). Rejects the sentinel input a1 == -1 and flag-state mismatches, lazily initializes the descriptor via MemoryAllocatorInit when no allocation exists, then either writes byte a1 at a decremented position or verifies it matches in match mode (flag 0x40). Returns the byte on success, -1 on failure.
- `0x00596A2E` **UnknownObject** — Character-type (ctype) retrieval for a wide character string with a one-time CRT mode auto-detection. On first call probes GetStringTypeW against the test string String2 and falls back to GetStringTypeA against String1, caching the chosen mode (1=Unicode, 2=ANSI) in dword_8D41D0. Unicode mode forwards straight to GetStringTypeW. ANSI mode measures the wide string via WideCharToMultiByte, converts it into an alloca'd buffer, then calls GetStringTypeA with the locale (falling back to dword_8D3F38) and a two-word sentinel window to detect the converted length, copying the result into the caller's lpCharType via sub_58B130. Stack buffers are guarded with __alloca_probe inside an SEH frame. Called by sub_58F939.

## Proposed classes

### SlabBuddyAllocator

Pool/slab allocator context node in the off_5E7968/off_5E796C linked list: prev/next list links at +0/+4, arena base at +0x10 (a 0x400000-byte VirtualAlloc reservation of 1024 x 4KB pages with a 2-DWORD-per-page page table), free-list table, lowest-free pointer and page-count bookkeeping. Created by initializeSlabBuddyAllocator (0x0059491A), page-trimmed by TrimAllocatorFreePages (0x00594AB4), and consumed by SlabBuddyAllocateMemory (0x00594C12) through 8-byte free descriptors carved by sub_594E1A.

Methods: `0x0059491A`, `0x00594AB4`, `0x00594C12`

- `this+0x00000000` `void* list_prev` (write, DERIVED)
- `this+0x00000004` `void* list_next` (read, DERIVED)
- `this+0x00000010` `void* arena_base` (read_write, DERIVED)

### SubbinBuddyAllocator

Subbin/buddy allocator object operating on a region base at +0xC and a per-subbin data base at +0x10: 16-byte-aligned size classes below 0x20 are tracked in the lower aggregate bitmap at +0, classes 0x20-0x3F in the upper aggregate bitmap at +4, with per-subbin bitmap arrays at +68/+196 relative to the subbin data base and a 516-byte subbin stride. Only the free path 0x00594624 is evidenced in this packet; the layout does not match the SlabBuddyAllocator pool-context layout and the two are kept separate.

Methods: `0x00594624`

- `this+0x00000000` `dword lower_size_class_bitmap` (read_write, DERIVED)
- `this+0x00000004` `dword upper_size_class_bitmap` (read_write, DERIVED)
- `this+0x0000000C` `void* region_base` (read, DERIVED)
- `this+0x00000010` `void* subbin_data_base` (read, DERIVED)

### PoolRegionFreeSpaceTable

Per-region free-space counter table owned by the a1 object of PoolBufferResize: an 8-byte-stride entry table whose entries start at a1+24 and whose region base pointer is read at a1+16; each entry pairs a free-size counter with a marker (241). Only 0x00594F3E is evidenced.

Methods: `0x00594F3E`

- `this+0x00000010` `void* region_table_base` (read, DERIVED)

### CRTFileHandleTable

CRT file-descriptor table: buckets of 36-byte records addressed as dword_8D4920[a1>>5] + 36*(a1&0x1F) with 32 records per bucket. Each record holds the OS handle at +0, an open/flags byte at +4 (bit 0 in-use, bit 2 cleared on a successful seek) and an embedded CRITICAL_SECTION at +12. Handle assignment, release, read, per-file lock leave, and the two guarded seek wrappers are evidenced; console standard-handle binding for descriptors 0-2 is gated by dword_5E65B4.

Methods: `0x00595924`, `0x005959A0`, `0x00595A1F`, `0x00595AC0`, `0x00595F11`, `0x00595F82`

- `this+0x00000000` `dword os_handle` (read_write, DERIVED)
- `this+0x00000004` `byte flags_byte` (read_write, DERIVED)
- `this+0x0000000C` `CRITICAL_SECTION critical_section` (read, DERIVED)

## Compatibility contracts

- **SlabBuddyFreeBlockAndBitmapContract** — The subbin/buddy free path aligns sizes to 16 bytes, derives the subbin from (block - region_base) >> 15, reads a slot count at block-4 and a total span dword, splits oversized free blocks into an allocated part plus a free remainder, coalesces an already-free block with its buddy, and maintains the aggregate size-class bitmaps (classes below 0x20 in bitmap 0, 0x20-0x3F in bitmap 1) plus per-subbin bitmap arrays. A replacement allocator must preserve this header convention and the 1/0 success contract.
- **AllocatorContextListAndAllocationContract** — Pool/slab allocator contexts are linked through the static off_5E7968/off_5E796C list; allocation round-robins via the off_5E9988 cursor, walks 8-byte free descriptors, carves via sub_594E1A, commits pages with VirtualAlloc, zeroes them via sub_58BB10, splits them into chained 4KB blocks recorded in the pool descriptor table, and falls back to creating a fresh context via initializeSlabBuddyAllocator whose first block is returned 256 bytes into the page.
- **TrimDecommitAndContextDestroyContract** — TrimAllocatorFreePages decommits free pages (page-table entries holding 240) via VirtualFree(MEM_DECOMMIT) up to a per-call page budget, marks entries -1, decrements the live page counter dword_8D41B8, and destroys the whole context via sub_594A5E when all 1024 page-table entries are -1.
- **CRTFileDescriptorTableContract** — CRT file descriptors are addressed as dword_8D4920[a1>>5] + 36*(a1&0x1F): OS handle dword at +0, flags byte at +4 (bit 0 in-use, bit 2 cleared on a successful seek), embedded CRITICAL_SECTION at +12. Descriptors 0-2 optionally bind or clear console standard handles gated by dword_5E65B4; invalid access records error 9 in the TLS error slot and returns -1.
- **CRTTlsErrorSlotContract** — CRT helper failures record an error code (9 for file-descriptor access, 42 for character conversion) through TLSOffsetGetter and clear the secondary TLS slot via TLSOffsetGetter_afd8, returning -1; successes return the handle, byte count, or 64-bit seek position.
- **LocaleGatedSingleCharConversionContract** — Single-character ANSI<->wide conversions short-circuit to a direct byte copy when no locale is set (dword_8D3F38 == 0) and the character fits one byte; otherwise conversion delegates to MultiByteToWideChar / WideCharToMultiByte with the global code page dword_8D3F48 and the cbMultiByte sequence length, and a conversion failure or default-character substitution yields TLS error 42.
- **FloatParser96BitResultContract** — The strtod-style parser writes a 96-bit result as a 16-bit low word at +0, a mid dword at +2, a high dword at +6 and a sign-or-exponent word at +10, returns classification codes 4 (no digits) / 2 (overflow) / 1 (underflow) / 0 (valid), and stores the end-of-parse pointer to *a2. The digit packing (sub_597621) and exponent decode (BitPackedDataDecodeViaLookupTable) helpers define the canonical representation.
- **MathErrorDispatchActionContract** — Math errors are dispatched by type code to action codes (types 1/5 to 8, 2 to 4, 3 to 17, 4 to 18, 6 to a reset of the error type with the handler skipped, 7 to 16, 8 to no handler). A non-zero sub_5919DA suppresses the handler; the FPU control word is restored via ReturnFPUControlWord; the resolved code comes from SetErrorCodeBasedOnInputRange when the error type is 8, the FPE flag dword_5E9AD0 is set, or StubReturning0() returns NULL.

## Unresolved

- SlabBuddyAllocator vs SubbinBuddyAllocator naming conflict: the packet names SlabBuddyFree in the same family as initializeSlabBuddyAllocator/SlabBuddyAllocateMemory, but its object layout (region base at +0xC, subbin data base at +0x10, 516-byte subbin stride, size-class bitmaps at +0/+4) does not match the pool-context layout of init/trim/allocate (list links at +0/+4, arena base at +0x10). The two are kept as separate classes until a packet proves common ownership.
- SubbinBuddyAllocator: the size-class mapping (class = (size >> 4) - 1, capped at 63) is implied by the bitmap arithmetic but the allocator object layout beyond offsets 0x0/0x4/0xC/0x10 is not present in this packet.
- SlabBuddyAllocator: whether the context is the free path's owner at all, and the exact free-list-table entry-to-block-size mapping, are not established; the -1 page-base sentinel and node layout offsets 2/3/4 are read from the decompiler only.
- PoolRegionFreeSpaceTable: owner a1 semantics and the marker value 241 at entry+4 are unproven; the descriptor a2 layout (data pointer at +0, length at +4, 248-byte extent) is inferred from pointer arithmetic and is not a named type.
- PoolRegionFreeSpaceTable: the prelabel auto-template claims a field getter at 0x10, but the raw source reads a1+16 as an array base; the raw source outranks that template and the two readings were not reconciled.
- StringParseViaDelegate: the role of the third argument dword_5E99A0 (parser context, format selector, or callback) is not evident from the raw source; only its address is deterministic.
- FloatToStringDigitFormatter: the source object at a3 (stream at +12, counter at +4) is of unknown type, and the rounding guard's sign condition v4 >= 0 is not fully recovered.
- CRTStringToFloatParser: the jpt_5962A8 jump-table dispatch is rendered as a switch by Hex-Rays; the state-id to meaning mapping (states 0-11) is only partially recoverable and several transitions are inferred.
- CRTStringToFloatParser: format scale arguments a5/a6 (added or subtracted into the exponent) have caller-dependent meaning; the classification codes 0-4 semantics are DERIVED, not independently proven; the output fields at +0/+2/+6/+10 versus the canonical 96-bit long double representation is DERIVED.
- MathErrorHandlerDispatch: the meaning of the action codes 4/8/16/17/18 and their mapping to MSVCRT _matherr / _fpieee_flt categories is not evidenced by the packet; the v16 flag construction is a decompiler artifact; the 16-bit FPU control word field meanings are unproven.
- CRTAllshl: on the count in [0x20, 0x40) path the decompiled text zeroes only the low dword and leaves the high dword uninitialized; canonical CRT ___allshl would place the shifted low dword into the high dword, but this packet cannot confirm that transfer.
- PushByteToBuffer: the concrete class of descriptor a2 and the semantics of the flag bits (0x1, 0x2, 0x40, 0x80) beyond the observed transitions are unproven; whether a2[1] counts bytes or elements is undetermined.
- CRTGetStringType: dword_8D41D0 is a process-global mode cache whose lifecycle and reset points are outside this packet; the sentinel-window idiom (v16[cchSrc-1]/v16[cchSrc]) upstream contract is not evidenced here; the TEB-relative globals are compiler-generated SEH bookkeeping, not application state.
- CRTFileHandleTable: bucket-array allocation and ownership of dword_8D4920 are unresolved; the 36-byte record layout beyond +0/+4/+12 is inferred from raw accesses; the open-count uNumber and the consumer of TLS error 9 are outside this packet.
- CRTFileHandleRelease: the flag byte bit-0 in-use interpretation is asserted only by symmetry with the assign twin; the error-reporting linkage to HandleCloseWithErrorReporting is not visible in this function body.
- sub_595F11: the relation to the structural twin sub_58C331 is proposed by clustering, not independently confirmed.
- StringFormatWith0x40Size: meaning of a2 and a3 depends on the sub_595AF9 contract, which is outside this packet; only the pinned size 64 is evidenced.
- WideCharToMultiByteSingle / MultiByteToWideCharSingle: dword_8D3F38, off_5E69C8 and cbMultiByte runtime roles are inferred from fill analysis; the default-character flag aliasing lpMultiByteStr and the reuse of lpWideCharStr != 0 as a buffer-count argument are uncertain decompiler artifacts.
- AmsgExitRuntimeError: the meaning of the exit argument 2u depends on the amsg runtime's contract; not evidenced in this packet.
- Unknown owners: 0x00595524, 0x005955AA, 0x00595733, 0x00595AE2, 0x00596089, 0x00596175, 0x00596245, 0x00596773, 0x00596840, 0x00596888, 0x00596A2E lack the surrounding type in this packet and are left unowned.
